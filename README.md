# BlawDiOh

### _A lipsync animation generator._

![Language](https://badgen.net/badge/language/Rust/red) ![License](https://badgen.net/badge/license/MIT/red)

## Background

I make [YouTube videos](https://youtube.com/c/ZombieNW) with animated avatars called [Blobs](https://zombienw.com/profile.png). As a programmer, I want to ease the animation process while keeping it personal. This program is a piece of that puzzle.

The first version, "AwDiOh", was a messy Python codebase with a little LLM stank on it. This new version is my way of remedying that while learning Rust.

## Architecture

This codebase is split into three Rust crates, `blawdioh-cli`, `blawdioh-engine`, and `blawdioh-render`.

#### `blawdioh-cli`

A lightweight cli. It makes `blawdioh-engine` generate keyframes and `blawdioh-render` render them into a video. On build, it copies the root `/assets` directory to the target output folder.

#### `blawdioh-engine`

The meat and potatoes of BlawDiOh. `blawdioh-engine` decodes an audio file into samples, takes the root mean square over an fps-determined interval, and generates KeyFrames based on custom animation parameters.

The KeyFrame object is a struct containing the frame number and respective EyeFrame and MouthFrame structs. Each of these has a texture-mapped State enum and a 2D offset vector. Factors like the frame number and rms value at the given frame determine the state and offset.

#### `blawdioh-render`

`blawdioh-render` renders an image for each KeyFrame generated by `blawdioh-engine` and pipes them into FFmpeg to make an `.mp4`. Relevant textures are loaded into an AssetBundle object and overlayed over each other frame-by-frame. Finally, the original input audio is mixed with the video and output as an `.mp4`.

## Future
